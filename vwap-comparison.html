VWAP Indicator — Options Backtester vs Simulated Trading

Side-by-side comparison of how each module implements and uses the VWAP indicator

Dimension ▲ Options Backtester ▶ Simulated Trading Notes
DATA SOURCE & EXTRACTION
Polygon Field vw from aggregate bars vwap / vw from SDK aggs Same Both use Polygon OHLCV+VWAP bars
Fallback Logic Falls back to close if vw is zero or missing Falls back to close if vwap is NaN Same Identical fallback strategy
SDK Handling Tries agg.vw → agg.vwap → dict lookup Tries agg.vwap → attribute → dict lookup Same Robust multi-path extraction
Caching Pre-fetched into indicators_cache['price'] keyed by timestamp SPY Parquet cache (2 yrs of 1-min bars); live bars via API Differs Batch pre-fetch vs. rolling cache
CALCULATION METHOD
VWAP Value Raw per-bar vw from Polygon (bar-level VWAP) Raw per-bar vwap from Polygon and computed rolling VWAP (period 14) Differs Backtester uses bar field only; Sim Trading also computes rolling VWAP
Rolling Calculation Not applicable — uses bar-level field directly computeVWAP(): TP = (H+L+C)/3, then Σ(TP×Vol) / ΣVol over 14-bar window Differs Sim Trading charts show full rolling VWAP overlay
SMA/EMA on VWAP Supported — can apply SMA/EMA to VWAP series in entry/exit conditions Not exposed as a configurable condition Differs Backtester adds this as a condition metric
TIMEFRAME & RESOLUTION
Base Resolution User-selectable (1min, 3min, 5min, …, 4hr via Timeframe dropdown) 1-minute bars; aggregated to selected view timeframe Differs Backtester lets you pick the bar timeframe per condition
Day Offset Configurable — Day 0, -1, -2 (compare today vs. yesterday's VWAP) Always current session — no historical day-offset for VWAP Differs Backtester supports multi-day lookback
Intraday Reset Bar-level VWAP resets each bar (Polygon provides per-bar VWAP) Session VWAP resets at market open (9:30 ET) each trading day Note Different semantics — bar vs. session scope
USAGE IN CONDITIONS / EXECUTION
Entry Signal VWAP in entry conditions: Price > VWAP, VWAP > SMA(VWAP), etc. Entry price defaults to bar's VWAP (most realistic fill estimate) Differs Backtester: logic gate; Sim Trading: execution price
Exit Signal VWAP in exit conditions: option exit when Price crosses below VWAP Exit price defaults to bar's VWAP for realistic slippage modeling Differs Same distinction as entry
Stop Loss / TP SL/TP triggers evaluated at each minute bar; VWAP used for execution price estimate SL/TP uses VWAP of trigger bar as the fill price Same Both use VWAP as realistic fill price for SL/TP
Right-Side Compare "Compare VWAP" available as comparator — e.g., SMA(20) > VWAP No configurable right-side comparison Differs Backtester supports cross-indicator VWAP comparison
EVALUATION LOGIC
Evaluation Path evaluate_price_conditions_with_cache() — reads bar.get('vw') per bar Per-tick JS loop — reads currentBar.vwap for execution Note Python backend vs. JS frontend evaluation
Batch vs. Real-time All bars pre-loaded; VWAP evaluated in vectorized batch over date range Evaluated tick-by-tick as simulation progresses in real time Differs Batch historical vs. real-time simulation
Multi-leg Support Single VWAP condition applies across all legs of a spread Single position — no multi-leg concept Note Options backtester supports complex spreads
Same — both engines behave identically Differs — implementations diverge Note — contextual difference
